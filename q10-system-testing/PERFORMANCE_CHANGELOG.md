## Runtime environment note

The 6543 transaction pooler remained intermittent from this host. Reproducible runtime measurements above use the configured 5432 session pooler (`DIRECT_URL`) without printing credentials. A transient pre-connect `P1001` was excluded from application latency and the retry succeeded; production startup already keeps readiness closed and retries before listening.

Before the resilience-cache revision, repeated benchmarking exposed remote-database tail latency: one healthy run completed in 2,321 ms while a degraded run took 7,868 ms. The subsequent scoped-cache and authentication single-flight revision produced a 2,009 ms cold complete-load result, dashboard HIT 118 ms, and Request Card HIT 394 ms. This materially reduces repeat and stale-cache latency, but a hard worst-case cold SLA still depends on database/network availability. Multi-instance production should use a shared Redis-compatible cache and place the API near PostgreSQL.
